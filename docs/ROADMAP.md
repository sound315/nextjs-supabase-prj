# ROADMAP: 병원 투약 안전 관리 시스템

## Phase 1: MVP 개발

**목표:** 핵심 기능인 약물 상호작용 경고 시스템 구현

### 환경 설정
- [ ] Next.js 15 프로젝트 초기화 (`create-next-app`)
- [ ] Supabase 프로젝트 생성 및 연동
- [ ] 환경변수 설정 (`.env.local`)
- [ ] shadcn/ui 설치 및 기본 레이아웃 구성
- [ ] 레이어드 아키텍처 폴더 구조 세팅

### 인증/권한
- [ ] Supabase Auth 로그인/로그아웃 구현
- [ ] 역할 테이블 설계 (간호사, 의사, 약사, 관리자)
- [ ] RLS 정책 설정 (역할별 접근 제어)
- [ ] 로그인 페이지 UI

### DB 스키마 설계 및 마이그레이션
- [ ] `products` 테이블 (제품 정보: 품목명, 품목코드, 제조사, 보험코드)
- [ ] `ingredients` 테이블 (성분 정보: 성분명 한글/영문, 성분코드)
- [ ] `product_ingredients` 테이블 (제품-성분 매핑 M:N, 함량 포함)
- [ ] `ingredient_interactions` 테이블 (조건 2: 성분 간 병용금기 조합 + 위험등급 + 사유)
- [ ] `patient_contraindications` 테이블 (조건 1: 환자 특이 금기 — 환자 ↔ 성분/제품)
- [ ] `reimbursement_restrictions` 테이블 (조건 3: 급여/보험 투약 제한 — 제품 단위)
- [ ] `patients` 테이블 (환자 기본 정보)
- [ ] `prescriptions` 테이블 (처방 목록)
- [ ] `prescription_products` 테이블 (처방별 제품 목록)
- [ ] `medication_logs` 테이블 (투약 이력 + 경고 처리 결과)
- [ ] `alert_logs` 테이블 (경고 발생 이력 + 금기 조건 유형)
- [ ] 시드(seed) 데이터 작성 (MVP용 샘플 제품/성분/금기 데이터 수동 입력)

### 약물 상호작용 경고 (핵심)
- [ ] 제품 검색/선택 UI (품목명 자동완성)
- [ ] 상호작용 검사 API (`POST /api/interactions/check`)
- [ ] 검사 로직 (Service): 제품 → 성분 추출 → 성분 쌍 조합 → 금기 DB 대조
- [ ] 동일 성분 중복 투여 감지 (복합제 포함)
- [ ] 경고 팝업 컴포넌트 (유형별 구분: 의료 위험 / 환자 특이 / 급여 제한)
- [ ] 투약 진행/중단 선택 처리
- [ ] 경고 이력 자동 저장

### 기본 관리 화면
- [ ] 환자 목록 및 상세 조회
- [ ] 처방 약물 입력/조회
- [ ] 투약 이력 조회
- [ ] 약물 DB 조회

## Phase 3: 식약처 데이터 연동 (자동화)

**목표:** 수동 시드 데이터를 공공 API 기반 자동 동기화로 전환

- [ ] 공공데이터포털(data.go.kr) API 키 발급 및 연동
- [ ] 식약처 의약품 허가정보 API → `products`, `ingredients` 자동 Import
- [ ] 식약처 DUR 병용금기 API → `ingredient_interactions` 자동 동기화
- [ ] 관리자 화면에서 수동 동기화 실행 버튼 제공
- [ ] 월 1회 배치 자동 동기화 (Vercel Cron)

> **데이터 전략**
> - 제품/성분/병용금기: 식약처 API로 Import (자동화 가능)
> - 환자 특이 금기: 병원 자체 등록 (공공 API 없음)
> - 급여/보험 제한: 수동 등록 (건보공단 API 연동 복잡)
