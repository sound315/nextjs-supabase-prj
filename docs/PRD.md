# PRD: 병원 투약 안전 관리 시스템

## 1. 프로젝트 개요

### 목적
환자에게 처방된 약물 간 위험한 상호작용을 사전에 감지하여, 간호사 및 담당자가 투약 전에 인지하고 중단할 수 있도록 지원하는 병원 투약 전산 관리 시스템

### 목표
- 투약 오류로 인한 의료 사고 사전 예방
- 약물 상호작용 경고를 실시간으로 담당자에게 전달
- 투약 이력 및 경고 발생 기록의 체계적 관리
- 의사, 간호사, 약사, 관리자 역할별 접근 권한 분리

---

## 2. 핵심 기능 목록

### 2.0 약물 선택 단위 및 성분 기반 검사 원칙

#### 약물 선택 단위: 제품 (Product)
- 사용자(간호사/의사)가 선택하는 단위는 **제품** (품목명 + 품목코드 기준, 예: "타이레놀 500mg 정")
- 각 제품에는 **1개 이상의 성분(ingredient)**이 매핑됨 (복합제는 여러 성분 포함)
- 약물 DB는 공공데이터포털(data.go.kr) 식약처 API 또는 수동 등록으로 구성

#### 금기 검사 기준: 성분 (Ingredient)
- 모든 금기 판단은 **성분 레벨**에서 수행
- 제품 선택 시 → 해당 제품의 성분 목록 추출 → 성분 기준으로 금기 DB 검사
- 복수 제품 선택 시 → 각 제품의 성분을 합산 → 성분 쌍(pair) 전체 조합 검사
- 동일 성분 중복 투여(예: 아세트아미노펜 함유 제품 2종 동시 선택)도 감지

#### 데이터 관계
```
제품(product) ─[M:N]─ 성분(ingredient)
성분 간 금기 조합(ingredient_interaction): 성분A ↔ 성분B
환자 특이 금기(patient_contraindication): 환자 ↔ 성분 (또는 제품 단위 직접 지정 가능)
급여 제한(reimbursement_restriction): 제품 단위로 등록
```

---

### 2.1 투약 금지 조건 검사 (핵심)

처방 제품 선택 시 아래 3가지 조건을 모두 검사하여 문제가 있으면 즉시 경고:

#### 조건 1: 환자 특이 금기
- 특정 환자에게 투여하면 안 되는 성분 또는 제품 (알레르기, 기저질환, 금기 이력 등)
- 환자 정보 + 선택 제품의 성분 목록으로 검사
- 경고 예시: `타이레놀 500mg 정 (아세트아미노펜) — 이 환자에게 투여 금지 (간질환 금기 기록)`

#### 조건 2: 성분 간 상호작용 금기
- 환자와 무관하게 함께 처방되면 위험한 성분 조합
- 선택된 제품들의 성분 합산 후 모든 성분 쌍(pair)을 금기 DB와 대조
- 동일 성분 중복 투여도 별도 경고 항목으로 처리
- 경고 예시: `아스피린(타이레놀) ↔ 와파린(쿠마딘) — 출혈 위험 증가`

#### 조건 3: 급여/보험 투약 제한
- 의학적으로는 투약 가능하나 국가 지원금/보험 급여 기준으로 투약 불가한 경우
- 제품 단위로 등록되며 별도 경고 등급으로 구분 (의료적 위험과 혼동되지 않도록)
- 경고 예시: `D099 (특정 항암제) — 급여 기준 초과: 해당 환자 보험 적용 불가`

#### 공통 경고 처리
- 위험 조건 감지 시 화면 팝업으로 즉시 표시
- 문제가 되는 약물 코드/이름을 명시적으로 표시
- 여러 조건이 동시에 감지되면 조건 유형별로 묶어 목록으로 표시
- 경고 확인 후 처방 진행 여부 선택 (중단 or 확인 후 진행)
- 모든 경고 발생 및 처리 결과는 로그로 저장

### 2.2 환자 및 처방 관리
- 환자 등록 및 기본 정보 관리
- 처방 약물 목록 입력 및 조회
- 투약 이력 기록 및 조회

### 2.3 약물 DB 관리
- **제품(product)** 등록/수정/삭제 (관리자) — 품목명, 품목코드, 제조사, 보험코드 등
- **성분(ingredient)** 등록/수정/삭제 (관리자) — 성분명(한글/영문), 성분코드
- **제품-성분 매핑** 관리 (관리자) — 제품별 함유 성분 및 함량 등록
- **환자 특이 금기** 등록/수정/삭제 (관리자/약사) — 환자 ↔ 성분/제품 단위
- **성분 간 상호작용 금기 조합** 등록/수정/삭제 (관리자/약사) — 성분A ↔ 성분B
- **급여/보험 투약 제한** 등록/수정/삭제 (관리자) — 제품 단위
- 각 금기 유형별 위험 등급 및 사유 설명 입력
- 공공데이터포털(data.go.kr) 식약처 API 연동을 통한 제품/성분 데이터 일괄 Import 기능 (향후 확장)

### 2.4 사용자 및 권한 관리
- 역할별 계정 관리 (간호사 / 의사 / 약사 / 관리자)
- Supabase Auth 기반 인증
- RLS 정책으로 역할별 데이터 접근 제어

### 2.5 경고 이력 로그
- 경고 발생 일시, 환자, 약물 조합, 담당자 기록
- 경고 후 투약 진행/중단 여부 기록
- 관리자/약사 조회 가능

## 4. 사용자 스토리

### 간호사
- 환자를 선택하고 투약할 약물을 입력했을 때, 기존 처방 약물과 위험한 조합이면 즉시 경고 팝업이 떠서 투약을 중단할 수 있다.
- 경고 내용(위험 이유, 등급)을 팝업에서 확인하고 투약 진행 여부를 결정할 수 있다.
- 투약 이력을 조회하여 해당 환자에게 어떤 약이 투여됐는지 확인할 수 있다.

### 의사/처방의
- 처방 약물 목록을 선택하는 즉시 위험 조합 여부를 확인할 수 있다.
- 경고 팝업에서 문제가 되는 약물 코드/이름 쌍과 위험 사유를 확인하고 처방 중단 또는 진행을 결정할 수 있다.
- 환자의 전체 처방 이력을 조회할 수 있다.

### 약사
- 위험 약물 조합 DB를 등록하고 관리할 수 있다.
- 경고 발생 이력을 조회하여 실제 투약 여부를 모니터링할 수 있다.

### 관리자
- 약물 정보 및 위험 조합 DB 전체를 관리할 수 있다.
- 사용자 계정 및 역할을 관리할 수 있다.
- 전체 경고 이력 및 투약 로그를 조회할 수 있다.

## 5. 비기능 요구사항

- 약물 상호작용 검사 응답시간: 1초 이내
- 경고 팝업은 담당자가 명시적으로 확인(클릭)해야만 닫힘
- 모든 경고 발생 및 처리 결과는 반드시 로그로 저장
- 역할별 RLS 정책으로 타 환자 데이터 접근 차단
- 모든 테이블에 `service_uid`, `job_uid` 컬럼 포함 (추적성 확보)
